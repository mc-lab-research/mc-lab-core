## Question and decision

### Question

Can an algorithm retain one selected transition from a local input-range
relation and later project its label after the producing range has expired,
source-unchanged across stored and ephemeral witnesses, by owning the range's
`transition_value_for_t`; or does durable transition evidence require a
separate model-provided persistence capability?

### Why it matters

The current structural contract deliberately guarantees only a transition
witness whose lifetime follows its producing range. At the same time, the
provisional execution direction suggests retaining transitions so labels,
weights, costs, probabilities, and other observations can be projected later.
No evidence currently establishes that `transition_value_for_t` is:

- constructible from every valid iteration observation;
- independent of the producing range and iterator;
- accepted by the same semantic observation CPOs after persistence;
- or sufficient to identify which parallel transition occurrence was selected.

If generic execution or counterexample results silently assume those
properties, the minimum `TransitionRelation` contract and the provisional
behavior representation are misaligned. Strengthening the relation globally
could, however, destroy the materialization freedom tested by ARC-001.

### Decision enabled

Choose the narrowest justified persistence boundary for transition-rich
algorithm results:

1. **KEEP** `TransitionRelation` minimal and use its reported transition value
   as algorithm-owned evidence;
2. **ADD/MOVE** persistence into a separate optional capability that explicitly
   converts a current witness into durable evidence;
3. **NARROW/REDESIGN** the provisional transition-rich execution direction if
   neither representation has acceptable leverage;
4. strengthen `TransitionRelation` only if persistence proves inseparable from
   every legitimate local-relation consumer.

The case does not select the final public spelling of an execution carrier or
persistence operation in advance.

### Scope

Included:

- finite labelled transition systems;
- one selected finite path of two transitions;
- local outgoing-transition ranges;
- stored stable witnesses and generated ephemeral witnesses;
- parallel transitions with one source and target but distinct labels;
- algorithm-owned behavior results that outlive all producing ranges;
- deferred label projection without re-enumerating the source relation;
- C++20 range value, proxy, ownership, and lifetime behavior;
- comparison of minimum-relation, optional-persistence, and eager-snapshot
  designs after the original attempt is preserved.

Excluded:

- global reachability and shortest-path policy;
- accepting-run search or model-checking correctness;
- infinite executions;
- mutation of the source model;
- serialization or cross-process identity;
- globally stable transition IDs;
- equality or hashing of persistent evidence except where the frozen consumer
  demonstrates a need;
- ordered-transition semantics as a property of the formal relation;
- weights, probabilities, costs, and other transition facets beyond labels;
- a universal execution representation;
- runtime plugin boundaries;
- and a foundational claim that all transition evidence can be persisted.

### Properties under investigation

- **P1 Representation independence:** the retention and replay consumers remain
  source-unchanged across stored and ephemeral witnesses.
- **P3 Algorithmic reuse:** one transition-selection result supports a separate
  later label projector without coupling selection to labelling.
- **P5 Semantic preservation:** the selected parallel occurrence retains the
  correct label rather than collapsing to its target state.
- **P6 Minimal structural assumptions:** ordinary local enumeration remains
  independent from persistence unless the experiment contradicts that split.
- **P7 Extension locality:** persistence-specific machinery is paid only by the
  consumers and models that require durable evidence.
- **P11 Capability orthogonality:** persistence is tested as a candidate
  capability distinct from the structural relation.

## Competing hypotheses

### H-A - The range value is sufficient algorithm-owned evidence

**Statement:** `transition_value_for_t<System, State>` can serve as the durable
transition value stored in a finite execution result without an additional
semantic capability.

**Mechanism:** The selection consumer materializes the current range
observation into the range's value type. That value owns everything required to
denote the selected transition, survives range destruction and iterator
advancement, and remains accepted by `transition_label` and `target`.

**Expected leverage:** A conventional C++ input-range value boundary supplies
persistence without adding a CPO, concept, descriptor hierarchy, stable model
storage, or eager semantic snapshot schema.

### H-B - Persistence is a separate optional capability

**Statement:** The minimum relation can expose valid ephemeral observations
whose reported value type is not, by contract, sufficient for later semantic
projection; models that support durable executions therefore need a separate
persistence capability.

**Mechanism:** A model-specific operation converts the current witness, while
valid, into an owning evidence value with an explicit lifetime and semantic
observation contract. Selection requires `TransitionRelation` plus this
optional capability; ordinary local consumers continue to require only the
relation.

**Expected leverage:** Stored models may persist a compact key or owning record,
while generated models may snapshot their current semantic transition. The
cost and requirement remain local to persistence-requiring consumers.

### H-C - Durable evidence is intrinsic to the relation

**Statement:** A separate capability cannot preserve the selected occurrence
with acceptable semantic clarity or machinery; a useful transition relation
must itself expose stable materialized witnesses.

**Mechanism:** Deferred projections, identity, and behavior construction depend
on witnesses that survive iteration, making stable storage, borrowed lifetime,
or a stronger range category part of the structural relation contract.

**Expected leverage:** Every transition-oriented algorithm can retain a witness
directly, at the cost of excluding genuinely ephemeral relations or forcing
them to materialize.

H-C is retained as a contradicting alternative, not a preferred design. It is
supported only if the controlled comparator shows that a separate persistence
boundary fails for a semantic reason rather than an apparatus defect.

## Experimental design

### Reference labelled transition system

Use a finite state domain `{0, 1, 2}` with this labelled relation:

```text
0 --advance--> 1
0 --bypass----> 1
1 --finish----> 2
```

The two transitions from `0` deliberately converge on the same target. A
state-only result cannot recover whether `advance` or `bypass` was selected.

The formal relation does not assign an order to those transitions. For the
controlled selection scenario, an injected selector policy observes each live
witness through the existing labelling vocabulary and accepts the occurrence
labelled `bypass`. The selection kernel invokes the policy but neither knows
how it decides nor receives the selected label as a value to store. This keeps
selection policy separate from evidence retention without relying on range
order. The same policy accepts the sole `finish` occurrence at state `1`.

The expected realized path is:

```text
State(0), Transition(bypass, 0 -> 1),
State(1), Transition(finish, 1 -> 2), State(2)
```

### Subjects and materializations

#### SUBJECT-STORED-EVIDENCE-01

- stored transition records with stable references;
- borrowed outgoing spans;
- range value type is the stored transition record;
- serves as calibration, not the adversarial hold-out.

#### SUBJECT-EPHEMERAL-EVIDENCE-01

- generated single-pass, non-forward, non-sized outgoing range;
- ephemeral proxy observation invalidated by iterator advancement;
- no persistent outgoing collection or stable occurrence address;
- semantically equivalent to SUBJECT-STORED-EVIDENCE-01;
- should reuse ARC-001's generated machinery when its validated result permits,
  rather than inventing an easier proxy.

#### SUBJECT-VALUE-HOLDOUT-01

- valid `TransitionRelation` and `TransitionLabelling` on its actual iteration
  observation;
- exposes a legitimate input-range value/proxy relationship that pressures
  whether `transition_value_for_t` can be constructed, retained, and observed
  later;
- remains hidden from the consumer author until the consumer and outcome
  classification are frozen if practical;
- must not be malformed merely to force H-A to fail.

The hold-out is development-visible unless an independent implementer is
available. Any loss of adversarial independence must be recorded as a threat to
validity.

### Consumers

#### CON-SELECT-RETAIN-01

**Semantic purpose:** Select one outgoing transition at each of two supplied
states and return an owning realized-path result that outlives every producing
range.

**Separation requirement:** The selection kernel requires target observation
and an injected witness-selector policy but does not itself require transition
labelling. The controlled selector may use `transition_label` while the witness
is live, but exposes only an accept/reject decision to the kernel. Neither the
kernel nor selector may copy the label into the realized-path result merely to
make the later projector pass.

**Frozen selection:** The supplied selector identifies the `bypass` occurrence
at state `0` and the sole `finish` occurrence at state `1` while each witness is
valid.

#### CON-PROJECT-LABELS-01

**Semantic purpose:** After selection has returned and all outgoing ranges and
iterators have been destroyed, project labels from the retained transition
evidence and compare them with `{"bypass", "finish"}`.

**Separation requirement:** The projector does not re-enumerate the source
relation and does not receive the original ephemeral witnesses.

#### Comparator: CON-EAGER-SNAPSHOT-01

After the original H-A attempt and any first failure are preserved, an explicit
comparator may copy `(source, label, target)` while the witness is live. This
tests the cost and coupling of a closed algorithm-owned snapshot schema. It is
not an authorized repair to the original frozen consumer.

### Minimum requirements

- local transition enumeration through `outgoing_transitions`;
- target observation while the current witness is valid;
- selection of one actual occurrence before iterator advancement through a
  frozen policy that returns only an accept/reject decision;
- an owning result whose lifetime is independent of the source ranges;
- later label projection for that same selected occurrence;
- exact preservation of the selected source, label, and target;
- the stored and ephemeral subjects implement the same reference semantics.

For the H-A attempt, the only proposed persistence mechanism is construction of
an owned `transition_value_for_t` from the current iteration observation. Any
additional model operation belongs to the H-B comparator and must not be added
before the original H-A result is preserved.

### Explicit non-requirements

- persistent evidence for consumers that never retain a witness;
- persistence after destruction of the source system itself unless the chosen
  evidence contract explicitly provides it;
- global transition identifiers;
- descriptor equality, ordering, or hashing;
- reconstruction of arbitrary transition facets not in the controlled subject;
- mutation through persistent evidence;
- zero-copy persistence;
- one universal behavior container;
- random access, `size()`, multipass enumeration, or a borrowed outgoing range;
- replay by re-enumerating the original relation;
- or strengthening every `TransitionRelation` model.

### Technical discriminator

The primary frozen attempt is:

1. select the configured transition occurrence while its witness is valid;
2. materialize only `transition_value_for_t` into the owning result;
3. destroy the outgoing range and advance beyond the witness;
4. later call the existing target and label vocabulary on the retained value;
5. compare the realized path with the frozen oracle;
6. run the same consumer sources against stored, ephemeral, and value-holdout
   subjects.

This separates three outcomes:

- H-A if the normal range value boundary is sufficient without extra semantic
  machinery;
- H-B if valid minimum-relation subjects require an explicit persistence
  operation but the separate capability restores unchanged selection and
  projection without strengthening the relation;
- H-C only if durable selection remains impossible or disproportionate without
  globally stable relation witnesses.

### Controlled phases

#### Phase A - Minimum-relation value attempt

Freeze both consumer sources, the oracle, reference semantics, value-boundary
mechanism, and outcome classifications. Run without a persistence CPO or eager
label snapshot. Preserve the first discriminating failure.

#### Phase B - Persistence comparator

Only after Phase A evidence is preserved and the Human Experiment Owner
authorizes comparison, evaluate:

- one small optional persistence operation with model-local adaptations;
- the explicit eager `(source, label, target)` snapshot comparator;
- the stronger stable-relation alternative only as a costed comparator, not as
  an automatic repair.

Phase B cannot rewrite Phase A's result.

### Semantic-integrity guardrails

- the retained evidence denotes the exact occurrence selected while live;
- the parallel `advance` and `bypass` transitions must never collapse merely
  because they share source and target;
- deferred labels must be `bypass`, then `finish`;
- every retained transition's target must equal the following state;
- no label may be recomputed from state pairs;
- no replay may silently re-enumerate the relation;
- no ephemeral proxy or reference may be used after invalidation;
- a persistence adapter must document whether it owns semantic facts, stores a
  model key, or depends on continued system lifetime.

### Architectural-complexity guardrails

Phase A may add only:

- one small realized-path test representation;
- the selection consumer;
- the deferred label projector;
- stored and ephemeral test subjects;
- compile-time lifetime/value checks and runtime oracle tests.

Phase B may add at most:

- one candidate persistence CPO and concept or equivalent explicitly named
  operation;
- one persistent evidence type per materially different model strategy;
- model-local adaptations;
- one eager-snapshot comparator.

Stop and assess leverage if support requires type erasure, shared ownership of
the entire model, a descriptor hierarchy, several associated-type layers,
global IDs, a persistent transition cache, or changes to unrelated facets.

## Expected observations

### Supports H-A when

- both consumers remain source-unchanged across all subjects;
- the selected range observation can be materialized into
  `transition_value_for_t` without representation branching;
- the retained value is valid after range destruction and iterator advancement;
- existing target and label operations accept that value later;
- the oracle path and labels agree;
- no persistence-specific CPO, stable model storage, re-enumeration, or eager
  semantic snapshot is required.

### Supports H-B when

- at least one valid subject cannot satisfy deferred replay through its range
  value alone for a reason permitted by the current relation and labelling
  contracts;
- that original failure is preserved;
- one separate persistence capability makes the frozen semantic consumers
  reusable with only persistence-local integration;
- ordinary local relation consumers and `TransitionRelation` remain unchanged;
- semantic integrity is preserved without a complete transition cache;
- the added machinery has positive leverage compared with eager snapshotting.

### Supports H-C when

- both the value-boundary and optional-capability designs fail for an intrinsic
  semantic or lifetime reason;
- the eager snapshot loses required selected-occurrence semantics;
- only stable relation witnesses preserve the frozen oracle;
- and the stronger relation contract has better demonstrated leverage than
  specialization or abandoning the provisional execution direction.

### Inconclusive when

- the subject violates C++ input-range requirements or the declared semantics;
- the selector does not identify the same intended occurrence;
- the hold-out is malformed solely to reject value materialization;
- the retained value is used after an undocumented system-lifetime dependency;
- compiler behavior cannot be separated from an implementation defect;
- Phase B changes a frozen Phase A consumer or oracle;
- or the comparator measures API spelling rather than persistence semantics.

## Challenge and interpretation

### Candidate challenge questions

- Is the value hold-out a legitimate input-range model or a manufactured
  failure?
- Does `transition_value_for_t` have any documented semantic meaning beyond the
  range's value type?
- Is later label projection a real separation of algorithm responsibilities or
  an artificial refusal to snapshot a known value?
- Does a persistence capability preserve open-ended transition observations,
  or merely move eager copying behind a CPO?
- Is selected occurrence identity actually semantic, or only an artifact of
  the injected selector policy? Does using a label-aware selector make deferred
  label projection artificial even though the label value is not retained?
- Could an execution result own a closed semantic record without problematic
  coupling?
- Does persistent evidence require the source system to remain alive, and is
  that acceptable?
- Would specialization for labelled paths have lower cost and clearer meaning
  than a generic persistence capability?
- Does the proposed capability generalize beyond this one small finite LTS?

### Interpretation

PENDING.

### Credible alternative interpretation

Even if H-B is supported, the result may show only that the provisional
transition-rich execution design is underspecified—not that SemTL needs a
public persistence capability. A private algorithm result type or
formalism-specific snapshot may have better leverage.

## Claim impact and decision

### Candidate affected Claim

No current Claim states that transition witnesses can be persisted. If ARC-002
is activated, it should investigate a new bounded Claim rather than silently
strengthening CL-001:

> Within the tested finite labelled-transition domain, a selected local
> transition can be converted into owning evidence that supports deferred
> semantic projection across stored and ephemeral witness representations.

This wording is not authorized by the draft.

### What remains unproven

- universal transition identity;
- persistence of arbitrary future facets;
- execution representations for other formalisms;
- infinite or streaming behavior retention;
- serialization, equality, hashing, or global IDs;
- source-system-independent descriptors;
- representation independence beyond the tested subjects;
- and positive leverage in production-scale algorithms.

### Candidate architectural actions

- **KEEP** range-value persistence if H-A has the strongest bounded support;
- **MOVE/ADD** an optional persistence capability if H-B has positive leverage;
- **NARROW** the provisional transition-rich execution direction if eager
  formalism-specific snapshots are clearer;
- **REDESIGN** the relation only if H-C survives the comparator and challenge;
- **INCONCLUSIVE** if the value hold-out or deferred projector does not provide
  a credible discriminator.

### ADR required

Only if validated evidence and a human decision establish a public persistence
capability, strengthen `TransitionRelation`, or replace the governing
transition-rich execution direction.

### Next question

If a separate persistence capability is supported, the next discriminator
should test whether its evidence can project a second independent transition
facet without changing the selection algorithm. If range-value persistence is
sufficient, the next question should test system-lifetime independence. If the
case is narrowed, investigate a formalism-specific execution value instead.
